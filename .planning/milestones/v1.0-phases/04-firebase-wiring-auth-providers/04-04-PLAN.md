**### Prerequisites**
- Firebase project created in Firebase Console
- FlutterFire CLI installed (`dart pub global activate flutterfire_cli`)

**### 1. Generate Firebase Options**
```bash
flutterfire configure --project=YOUR_PROJECT_ID
```
This replaces `lib/firebase_options.dart` (the stub) with real configuration. After this step, `flutter run` will initialize Firebase instead of falling back to dev mode.

**### 2. Google Sign-In Setup**

**Android:**
- Register SHA-1 fingerprints in Firebase Console > Project Settings > Your Apps > Android app > Add Fingerprint
- Debug SHA-1: `./gradlew signingReport` (look for `SHA1` under `debugAndroidTest`)
- Release SHA-1: `keytool -list -v -keystore <your-release-keystore> -alias <alias>`
- The `serverClientId` (Web OAuth client ID) is needed for `google_sign_in` on Android. Find it in Google Cloud Console > APIs & Services > Credentials > Web client (auto-created by Firebase). If `FirebaseAuthService._webClientId` returns empty, update it with this value.

**iOS:**
- Add the reversed client ID to `ios/Runner/Info.plist` under `CFBundleURLTypes`:
```xml
<key>CFBundleURLTypes</key>
<array>
  <dict>
    <key>CFBundleURLSchemes</key>
    <array>
      <string>com.googleusercontent.apps.YOUR_REVERSED_CLIENT_ID</string>
    </array>
  </dict>
</array>
```
The reversed client ID is in `GoogleService-Info.plist` under `REVERSED_CLIENT_ID`.

**### 3. Apple Sign-In Setup**

**iOS only (per D-06):**
1. Open the project in Xcode
2. Select Runner target > Signing & Capabilities
3. Click `+ Capability` > `Sign in with Apple`
4. In Apple Developer Portal > Certificates, Identifiers & Profiles > Identifiers:
   - Select your App ID > enable `Sign in with Apple`
   - If using web/Android redirect flow: create a Services ID, configure domains and return URLs

**### 4. App Check (Release Builds Only)**
App Check is activated automatically in release builds (`kReleaseMode`):
- Android: Play Integrity (requires Play Console enrollment)
- iOS: App Attest (requires iOS 14+; skeleton floor is iOS 15)

No debug-token configuration needed — dev builds skip App Check entirely.

**### 5. Crashlytics**
Crashlytics is wired automatically when Firebase is initialized:
- `FlutterError.onError` catches Flutter framework errors
- `PlatformDispatcher.instance.onError` catches async Dart errors
- `Isolate.current.addErrorListener` catches spawned isolate errors
- Collection is disabled in debug builds — only release crashes are reported

**### Dev Mode (No Firebase)**
The skeleton works without Firebase. If `firebase_options.dart` is the stub (no `flutterfire configure` run), the app:
- Falls back to `'dev'` DI environment
- Registers `FakeAuthService` (in-memory, any email/password works)
- Does not register Firebase Analytics, Performance, or Firestore
- Does not activate Crashlytics or App Check

This preserves the `clone -> flutter run` DX promise.
