  <action>
1. Run `fvm flutter pub get` to regenerate `pubspec.lock` and `.flutter-plugins-dependencies` against Flutter 3.41.5:
   ```bash
   fvm flutter pub get
   ```
   This also triggers l10n generation (because `flutter: generate: true` is set in pubspec.yaml).

2. Run build_runner to regenerate all generated Dart files (injection.config.dart, router.gr.dart, objectbox.g.dart):
   ```bash
   fvm dart run build_runner build --delete-conflicting-outputs
   ```

3. Run `pod install` in the ios/ directory to regenerate Podfile.lock and install pods:
   ```bash
   cd ios && pod install && cd ..
   ```
   If pod install fails due to repo issues, run `pod repo update` first, then retry.

4. Verify the regenerated `.flutter-plugins-dependencies` does NOT reference `web`, `macos`, `linux`, or `windows` platform entries for any plugin. Check with:
   ```bash
   grep -c '"web"' .flutter-plugins-dependencies
   grep -c '"macos"' .flutter-plugins-dependencies
   grep -c '"linux"' .flutter-plugins-dependencies
   grep -c '"windows"' .flutter-plugins-dependencies
   ```
   These may still appear as platform declarations in the plugin metadata (since plugins support multiple platforms), but there should be no top-level platform registrant entries for non-mobile platforms.

5. Run `fvm flutter analyze` to verify no analysis errors (warnings are acceptable -- Phase 2 handles lint upgrade):
   ```bash
   fvm flutter analyze
   ```

6. Verify the app can be built (at minimum, analyze passes). If an iOS simulator or Android emulator is available, attempt:
   ```bash
   fvm flutter build apk --debug
   ```
   A debug APK build confirms the entire Android toolchain (AGP, Kotlin, Gradle) is functional after the rebase.
