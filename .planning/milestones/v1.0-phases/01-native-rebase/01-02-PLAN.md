**For Groovy DSL (`build.gradle`):**

1. At the TOP of `android/app/build.gradle`, BEFORE the `plugins {}` or `android {}` block, add the key.properties reader:

```gradle
// --- Release signing configuration (per D-07) ---
// Priority: key.properties file > environment variables > no signing (release build fails)
def keystorePropertiesFile = rootProject.file("key.properties")
def keystoreProperties = new Properties()
def hasKeystoreFile = keystorePropertiesFile.exists()
if (hasKeystoreFile) {
    keystoreProperties.load(new FileInputStream(keystorePropertiesFile))
}

def hasEnvVars = System.getenv("ANDROID_KEYSTORE_PATH") != null
```

2. INSIDE the `android {}` block, BEFORE `buildTypes {}`, add the `signingConfigs` block:

```gradle
    if (hasKeystoreFile || hasEnvVars) {
        signingConfigs {
            release {
                if (hasKeystoreFile) {
                    storeFile file(keystoreProperties['storeFile'])
                    storePassword keystoreProperties['storePassword']
                    keyAlias keystoreProperties['keyAlias']
                    keyPassword keystoreProperties['keyPassword']
                } else {
                    storeFile file(System.getenv("ANDROID_KEYSTORE_PATH"))
                    storePassword System.getenv("ANDROID_KEYSTORE_PASSWORD")
                    keyAlias System.getenv("ANDROID_KEY_ALIAS")
                    keyPassword System.getenv("ANDROID_KEY_PASSWORD")
                }
            }
        }
    } else {
        logger.warn("WARNING: No release signing configuration found.")
        logger.warn("  -> Create android/key.properties from key.properties.template (local dev)")
        logger.warn("  -> Or set ANDROID_KEYSTORE_PATH, ANDROID_KEYSTORE_PASSWORD, ANDROID_KEY_ALIAS, ANDROID_KEY_PASSWORD (CI)")
        logger.warn("  -> Release builds will fail until signing is configured. See README.md > Release Signing.")
    }
```

3. In the `buildTypes { release { ... } }` block, set the signing config conditionally (per D-08 -- no `signingConfig` when neither source present):

```gradle
    buildTypes {
        release {
            signingConfig = (hasKeystoreFile || hasEnvVars) ? signingConfigs.release : null
        }
    }
```

If the fresh template already has a `release` buildType block (it likely does with `signingConfig = signingConfigs.debug`), REPLACE the `signingConfig` line. Keep any other settings the fresh template includes (e.g., `minifyEnabled`, `shrinkResources`, `proguardFiles`).

**README update (per D-09):**

1. Add a `## Release Signing` section to README.md. Place it AFTER the `### Firebase` section (line 45) and BEFORE `### Troubleshooting` (line 47). Use the existing heading style (level 2 `##` for top sections):

```markdown
## Release Signing

The skeleton uses a `key.properties` file for local release signing and environment variables for CI.

### Local Setup

1. Generate a keystore:
   ```bash
   keytool -genkey -v -keystore android/app/keystore.jks -keyalg RSA -keysize 2048 -validity 10000 -alias upload
   ```

2. Copy the template and fill in your values:
   ```bash
   cp android/key.properties.template android/key.properties
   ```

3. Edit `android/key.properties` with your keystore path, passwords, and alias.

4. Build a release APK:
   ```bash
   fvm flutter build apk --release
   ```

### CI Setup

Set these environment variables instead of using `key.properties`:

| Variable | Description |
|----------|-------------|
| `ANDROID_KEYSTORE_PATH` | Path to the `.jks` keystore file |
| `ANDROID_KEYSTORE_PASSWORD` | Keystore password |
| `ANDROID_KEY_ALIAS` | Key alias (e.g., `upload`) |
| `ANDROID_KEY_PASSWORD` | Key password |

> **Note:** `key.properties` and `*.jks` files are gitignored. Never commit signing secrets.
```
